# Review: m1-platform-foundation

Reviewed commit: `d21aef46b1c7d8d581ab0c4174d7f25127c10eaa`

The project was activated in Serena and reviewed against the change's specs, design and tasks. Context7 was used for relevant third-party documentation, including Werkzeug, Waitress and Flask-Alembic. Official platform, Caddy and uv documentation supplied additional references.

**Everything has not been implemented**, despite all **24 tasks** being checked off. The review was read-only; no source files were changed, and the working tree was clean when the review finished.

The main findings, ordered by severity:

1. **[P1] `serve` does not configure the application.** It calls `create_app()` without passing the selected data root or loading environment configuration. A startup probe showed readiness returning **503 "Data root not configured"**, an unknown Host returning **200**, and configured CORS settings absent. The CLI also silently defaults to `server`, contrary to the explicit-mode requirement. [server.py:45](src/litfoundry/server.py#L45), [cli.py:57](src/litfoundry/cli.py#L57)

2. **[P1] Windows permissions do not implement the promised protection.** The DACL remains unprotected: a real Windows probe returned `SE_DACL_PROTECTED=False`. Permissions are applied only to the root, leaving existing child ACLs unchanged, and the configured service identity is replaced with the current user. The fallback is `chmod`, rather than the specified `icacls`. [filesystem.py:186](src/litfoundry/filesystem.py#L186). Microsoft confirms that this `SetFileSecurity` operation does not propagate directory security to children. [Microsoft documentation](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-setfilesecurityw)

3. **[P1] Proxy trust is incorrect in both directions.** `ProxyFix` trusts one forwarded hop unconditionally; the configured proxy addresses are informational. An untrusted-peer probe successfully changed the apparent IP, scheme and host, bypassing the Host check. Conversely, the actual Waitress defaults strip forwarded headers because `serve` supplies no trusted-proxy settings. [middleware.py:31](src/litfoundry/middleware.py#L31). These behaviors were checked against Context7's [Werkzeug](https://github.com/pallets/werkzeug/blob/main/docs/deployment/proxy_fix.rst) and [Waitress](https://github.com/pylons/waitress/blob/main/docs/arguments.rst) documentation.

4. **[P1] Initialization fails from the built wheel.** An offline wheel build succeeded, but it contained only the migration template, without the catalogue migration environment or revisions. Initialization from the extracted wheel failed with **"Path doesn't exist: ...\\migrations\\catalog"** because migration discovery assumes the repository layout. [engine.py:127](src/litfoundry/catalog/engine.py#L127)

5. **[P1] Logging can disclose secrets and is disconnected from startup.** Redaction touches the message, but exception text is appended afterward without redaction. A synthetic password survived in the emitted JSON. Also, startup never calls `setup_logging`; timestamps use local time while appending `Z`, and the required event field is absent. [logging.py:65](src/litfoundry/logging.py#L65), [logging.py:97](src/litfoundry/logging.py#L97)

6. **[P1] The reference Caddy configuration contains invalid syntax.** `timeout 30s` is not a supported `reverse_proxy` subdirective. Its test accepts exit code **1**, allowing validation failure to pass. This finding is based on the official syntax/parser; Caddy was unavailable locally. [Caddyfile.example:52](packaging/caddy/Caddyfile.example#L52), [test_deployment.py:55](tests/test_deployment.py#L55), [Caddy reference](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)

7. **[P2] Health checks can report an unusable catalogue as healthy.** Both checks rely on `SELECT 1`, which does not establish that application tables or migrations exist. An empty database plus the marker file reported **healthy/ready**. Schema checks and much of the required version, disk and deployment metadata are missing. [health.py:71](src/litfoundry/api/health.py#L71), [status.py:76](src/litfoundry/status.py#L76)

8. **[P2] Initialization omits required directories.** Fresh initialization creates neither `trash/` nor `backup_staging/`. Repeated initialization also reports "Initialized" rather than explaining that the root was already initialized. [initialization.py:36](src/litfoundry/initialization.py#L36)

9. **[P2] Path containment is implemented as a helper but bypassed by the log endpoint.** The endpoint opens its path directly. A symlink from `logs/litfoundry.log` to a synthetic file outside the data root was followed and its contents returned. [admin.py:69](src/litfoundry/api/admin.py#L69)

10. **[P2] Platform filesystem handling is incomplete.** Linux detection assumes a fixed filesystem-type column despite variable optional fields; a valid mocked NFS mount was accepted. macOS reads `/etc/mnttab` instead of implementing the specified `statfs` detection. Its default root is also user-scoped, without the required system-wide mode. [filesystem.py:133](src/litfoundry/filesystem.py#L133), [config.py:54](src/litfoundry/config.py#L54). [Linux mountinfo format](https://man7.org/linux/man-pages/man5/proc_pid_mountinfo.5.html)

11. **[P2] Product constants contradict the exact required wording.** The tagline should be **"From literature to insight."** The description is also different, and `get_about_text()` lacks the licence and administrator disclosure. GUI construction is deferred, but the constants already marked complete are incorrect. [constants.py:8](src/litfoundry/constants.py#L8), [product-identity specification](openspec/changes/m1-platform-foundation/specs/platform/product-identity/spec.md#L9)

12. **[P2] The claimed verification is incomplete.** Ruff reports **361 issues** and mypy **9 errors**. CI uses `uv sync` without selecting the optional `dev` extra containing its checking tools. The offline test never blocks outbound networking, and its retryable-error test merely asserts that an app exists. [ci.yml:37](.github/workflows/ci.yml#L37), [test_offline_operation.py:150](tests/test_offline_operation.py#L150), [uv extras documentation](https://docs.astral.sh/uv/concepts/projects/sync/#syncing-optional-dependencies)

Some foundations work: CLI/package naming, the Flask blueprint structure, the checkout's catalogue baseline and SQLite pragmas, portable AES-GCM encryption, and the write-only secret helper.

The GUI screens, real admin authorization and session integration are **explicitly deferred to `m1-local-identity`**. They remain unfinished: readiness and logs currently allow anonymous access when configured. The change itself says to archive the three M1 changes together. [tasks.md:45](openspec/changes/m1-platform-foundation/tasks.md#L45)

Validation completed on Windows: **250 passed, 13 skipped**, plus focused probes reproducing the defects above. Linux/macOS runtime behavior and a complete Caddy/HTTPS deployment remain unverified. Security and correctness have blocking findings; maintainability checks fail; performance has only limited static coverage. **This change should not be signed off as complete.**
